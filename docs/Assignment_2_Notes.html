No, the “Harris” and “Kamala Harris” series are not the same. Their values and patterns differ because Google treats them as two different search terms. “Kamala Harris” captures searches containing the full name, while “Harris” captures searches for the word “Harris,” which may refer to Kamala Harris or to unrelated people, places, and organizations.

The gap shows that a search term is not necessarily the same as the concept the researcher wants to measure. The search term “Harris” is broad and ambiguous because it can capture searches unrelated to Kamala Harris. Therefore, it has lower measurement validity as an indicator of public interest in Kamala Harris. The more specific term “Kamala Harris” provides a closer measure of the intended concept, although it may still miss searches using other wording. Researchers must carefully choose search terms and explain how those terms operationalize the concept they intend to study.

    1. The R method is more reproducible because the code records the search terms, geography, time period, category, and search type. Another researcher can rerun this code. However, they may not obtain exactly the same numbers because Google Trends uses sampled and normalized data. In addition, today+5-y is a moving window, so running it on another date covers a different five-year period. The website method is less reproducible because the selections are made manually. Unless the researcher records every setting and the retrieval date and time, another person may not know precisely how the CSV was created.

  1. R provides better provenance because the code documents where the data came from and how the query was constructed. The returned R data also include variables such as: keyword, geo, time, gprop, and category. The website CSV mainly contains the dates and interest values. It may not preserve every choice used to generate the download. Therefore, the researcher must separately record the terms, geography, period, category, search type, and retrieval time.

  2. R is more efficient for large or repeated data-collection tasks. The code can automate downloading, organizing, plotting, and saving multiple queries. Collecting fifty terms manually from the website would require many searches and downloads, increasing the time required and the possibility of human error. However, Google Trends limits the number of terms that can be compared in one query. Fifty terms would need to be divided into several batches. Because Google normalizes each query separately from 0 to 100, the results from different batches are not automatically comparable. A researcher may need to include the same reference term in every batch and use it to connect or rescale the results.

  3. Both methods are fragile, but in different ways.

The website method may break or produce inconsistent data when:

  1. Google changes the website interface.
  2. A researcher accidentally chooses the wrong setting.
  3. The downloaded file format or column names change.
  4. Different browsers or dates produce different defaults.
  5. The researcher forgets to document a setting.

The R method may break when:

  1. Google changes the service used by gtrendsR.
  2. The package becomes outdated.
  3. Google imposes rate limits.
  4. The internet connection fails.
  5. A query returns empty data.
  6. Column names, formats, or temporal intervals change.
  7. Values such as <1 produce conversion warnings or missing values.
