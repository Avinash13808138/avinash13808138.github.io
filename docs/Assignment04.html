Part 1: Practice scraping Books to Scrape

Turning information displayed on five webpages into one structured dataframe. Each row represents one book listing.

Part 1(a): Run the sample against the practice website

  • Books to Scrape is designed for scraping practice.

  • Its static HTML lets us practice extracting information without needing JavaScript tools.

  • We first read page 1 and inspect the extracted results before repeating the process across more pages.

Part 1(b): Extract titles, prices, and ratings from five pages

  • We extract each book’s title, price, and star rating.

  • We convert the price text into a numeric variable called price_gbp.

  • We repeat the extraction for pages 2–5 and reuse the page 1 results.

  • We combine the five page-level dataframes into books_all.

  • The expected result is 100 book listings, with 20 listings from each page.

  • The additional page column records where each listing came from.

Extracting title, price, and rating and binding the scraped data from the first 5 pages into one data frame.

## ---- 1. The sandbox: books.toscrape.com ------------------------------------
## Built and published for scraping practice. 1,000 books, 50 pages, no
## JavaScript. Learn the verbs here before you point them at anyone's server.

# Read the first page of book listings
books_pg <- read_html(
  "https://books.toscrape.com/catalogue/page-1.html"
)

books <- tibble(
  title  = books_pg |> html_elements("article.product_pod h3 a") |> html_attr("title"),
  price  = books_pg |> html_elements("article.product_pod p.price_color") |> html_text2(),
  rating = books_pg |> html_elements("article.product_pod p.star-rating") |>
             html_attr("class") |> str_remove("star-rating ")
) |>
  mutate(price_gbp = parse_number(price))

Part 2: Scrape and clean Wikipedia tables

Extracting tables from a real website, adapting the program to another table, and cleaning the results into usable dataframes.

Part 2(a): Scrape the foreign-exchange reserves table

  • We checked the page’s robots rules before fetching it.

  • We inspected the candidate tables and extracted the reserves table.

  • We identified the including-gold amount column: foreign_exchange_reserves.

  • Its unit is US$ millions.

  • We retained the country, reserves amount, and reporting date.

Part 2(b): Scrape a different table and explain what changed

  • We changed the target to Wikipedia’s countries-and-dependencies population table.

  • The country column changed from country_as_recognized_by_the_un to location.

  • The amount column changed from foreign_exchange_reserves to population.

  • The reporting-date column changed from last_reporteddate to date.

  • Therefore, the column-selection code needed changing.

  • The reserves table contained two additional header rows that needed removal.

  • Both tables used day–month–year dates, so the same date-conversion function worked for both.

What broke and why: Column-specific code cannot automatically transfer between tables with different names. The placeholder errors we encountered were caused by unreplaced example names; they were not evidence that Wikipedia had changed its page.

Part 2(c): Clean the dataframes

  • Standardized column names.

  • Removed bracketed footnotes, thin spaces, nonbreaking spaces, and extra whitespace.

  • Removed unnecessary columns.

  • Removed repeated country headers and any Total or World rows.

  • Converted reserve amounts and population counts into numbers.

  • Converted reporting dates into R dates.

  • Preserved the original amount and date text to check conversions.

  • Added checks to identify missing or unsuccessfully converted values.

Part 3: Fetch the same quantity through an API

Obtaining reserves through a structured data interface and comparing them with the scraped Wikipedia figures.

Part 3(a): Fetch World Bank reserves

  • We used the WDI package to request indicator FI.RES.TOTL.CD, total reserves including gold in current US dollars.

  • One WDI() call requested observations for 2015–2024.

  • The results were stored in reserves_api.

  • Each row represents a country or aggregate in one observation year.

Part 3(c): When is scraping the right tool?

Web scraping is the right tool when the required data are available on webpages but cannot be obtained through a suitable API, downloadable dataset, or bulk export. It should be used when the website’s robots rules and Terms of Service permit the intended collection, with reasonable request rates and checks to detect changes in the page structure.

## ---- 3b. Prepare World Bank reserves for comparison ------------------------
## Keep countries and economies rather than regional aggregates.
## Convert current US dollars to US$ millions.

reserves_wb <- reserves_api |>
  filter(!is.na(region),
         region != "Aggregates",
         !is.na(FI.RES.TOTL.CD)) |>
  group_by(iso2c) |>
  slice_max(year, n = 1, with_ties = FALSE) |>
  ungroup() |>
  select(country_wb = country,
         iso2c,
         wb_year = year,
         wb_usd = FI.RES.TOTL.CD) |>
  mutate(wb_usd_million = wb_usd / 1000000)

## ---- Match countries and calculate differences ---------------------------

reserves_comparison <- reserves_wiki |>
  left_join(reserves_wb, by = c("country" = "country_wb")) |>
  mutate(difference_million = wiki_usd_million - wb_usd_million,
         difference_percent = if_else(
           !is.na(wb_usd_million) & wb_usd_million != 0,
           100 * difference_million / wb_usd_million,
           NA_real_))
